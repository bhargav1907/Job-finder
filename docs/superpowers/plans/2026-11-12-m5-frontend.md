# M5 Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the FLA Job Finder frontend: upload a resume, refine filters, and read a ranked shortlist with fit scores, reasons, and gaps.

**Architecture:** A single-screen React SPA with three responsive panes (candidate file, shortlist, case file). Server state lives in TanStack Query; the only fetch module is `src/api.ts`. Selection is encoded in the URL so a role is deep-linkable without a router. Tailwind v4 tokens carry the "placement desk" palette and typography.

**Tech Stack:** Vite 8, React 19, TypeScript strict, Tailwind CSS 4, TanStack Query 5, Fontsource variable fonts, Vitest + Testing Library, Playwright + axe.

**Spec:** `docs/superpowers/specs/2026-11-12-m5-frontend-design.md`

## Global Constraints

- Dark is the default theme; light mode must be complete, not a fallback.
- No fetch call outside `frontend/src/api.ts`.
- No new runtime dependency beyond TanStack Query and the two Fontsource packages.
- Score is 0–100; INR salary is annual rupees displayed as LPA; missing pay says "Pay not stated".
- `remote: false` is never relabeled "on-site".
- The demo badge is visible at every viewport.
- Never claim live postings or invented parse progress.
- WCAG AA contrast, visible focus, reduced-motion support, keyboard-operable shortlist.
- Copy rules: sentence case; no all-caps eyebrows; no `A · B · C` meta strings; no arrows appended to buttons.

## Review Focus

- A resume id in localStorage that no longer exists in the database → the app must clear it and show the upload screen, not a broken pane.
- An empty corpus (no ingest run) → the app must say how to load seed jobs, not just "no matches".
- A role with no salary, no gaps, and `reranked: false` → each section must explain the absence honestly.
- A very long role title, company, skill list, or gap list at 390px wide → the layout must wrap or truncate without overflow.
- A user navigating the shortlist with the keyboard or a screen reader → focus must move with selection and the result count must be announced.
